## 2. 信息重叠矩阵

记 H50(q) 为严格 target 前最后至多 50 条 observed 历史，n=|H50|；L(q) 为当前可观察 train 起点以来、不截断的严格前缀。L 不代表真实 lifetime。重复曝光沿冻结语义保留，不先去重。

F3 实际为 `timespent` 时长桶 T + `timespent/duration` 比例桶 R，**没有单独的 duration 桶**。在实数上：

`u_F3 = mean(item_emb) + Σ_b p_ts(b)T[b] + Σ_c p_ratio(c)R[c]`。

它已编码两组边际桶频率的线性投影，不直接保留原始比例均值、精确累计数或 item×ratio 交互。例如 ratio 全为 0.2 与全为 0.4，ratio 桶相同，原始均值不同。浮点舍入差异不构成有意义的顺序编码。

F4 再加 `mean(P[position_bucket]) + mean(G[week_gap_bucket])`。位置从最后有效事件倒数，均值 P 只由 n 决定；G 是 `week(last_history)-week(event)` 的桶分布，表示相对活动跨度，未使用 target/query 周。它没有让近期 item 权重更大。遵循 decision_log 04:5x 最新措辞：已有增益主要是**活动时间跨度（周间隔分布）先验**，不能宣称“历史长度先验有效”或“近期加权有效”。

Q3 为 F3 均值 + `Len[bucket(n)] + Act[bucket(distinct_history_weeks)]`，两数都只看 H50，**不是 F4 上叠加**；F4 P/G 被移除。distinct weeks 不等于首末跨度，例如 week 1/5/9 是 3 个活跃周、跨度 8；也不能从粗化 gap 桶精确恢复 distinct weeks。

| 拟议特征 | F3 重复 | F4 重复 | Q3 重复 | 新增与解释限制 |
|---|---|---|---|---|
| U2：N_exp(L) | F3 均值丢总量；可间接相关，非精确计数 | L≤50 时 n=N_exp，P 已含 n 的函数；L>50 后 n 饱和 | Q3 显式窗口长度桶，L≤50 时重复；>50 后看不到累计规模 | 主要新增截断外规模；改用 H50 只能称窗口曝光数 |
| U2：N_like(L) | F3 不读 like 位，ratio 相关不等于 like 计数 | F4 不读 like 位 | Q3 只含长度/活跃周数 | 显式累计正反馈量；与曝光数相关，组实验不能归因单字段 |
| U3：mean(ts/dur) | 强重叠 ratio 桶分布；原始均值补桶内值和 >1 幅度 | F4 内含 F3，同样重叠 | Q3 内含 F3，同样重叠 | H50 下只补细粒度；若换 L 又同时改长期窗口 |
| U3：N_like/N_exp | F3 未读 like；与 ratio 可能相关 | F4 没有反馈率 | Q3 没有反馈率 | 新增 like 倾向；与 U2 两精确数确定相关，分桶后冗余程度待测 |
| U3：主要 place/platform | F3 不读场景 | F4 不读场景；F5 才读，F5 不在 anchor 内 | Q3 不读场景 | 新增场景分布摘要；众数丢多样性，平台偏好不能直接称内容口味 |

矩阵是结构判断，未计算相关系数、互信息或效果，均 UNKNOWN。若 F7 有效，先说“相对 F4-T010 用户级聚合提供增量”，不能直接归因“新增口味信息”。

## 3. 三种口径与建议（待裁决）

| 方案 | U2 | U3 | 取舍 |
|---|---|---|---|
| A，建议 | L 的累计曝光/like 数 | H50 的 ratio 均值、like 率、place/platform 众数 | U2 检验截断外活动；U3 与 F3/F4 用同事件集，减少窗口混杂；需新前缀 sidecar |
| B | H50 曝光/like 数 | 同 A | 易复用现有 side/ctx；曝光数与 F4/Q3 更重复，回答不了累计活动问题 |
| C | 同 A | L 上四项画像 | 更长期；窗口与统计形式同时变化，解释混杂更大 |

建议 A；最终窗口、字段组、pooling 接法由 Kiro 审阅，不写成冻结定义。修改方案必须同步修改 oracle 和矩阵，不能结果后变更。

### U2 建议公式

按 `(week, physical_row_ordinal)` 扫描：在每个训练 target 处先 snapshot 用户 `N_exp`、`N_like`，之后才 update 当前行。N_exp 计所有严格前缀曝光；N_like 只计其中 like=True。零 like 是有效数值。当前 target 的 like 不参与本次计数，不用 full-train 用户总量回填。

validation 固定累计 train 00–24；week25 不吸收，即使 target 是 week25 后面的行，也不吸收其之前的 validation 行。计数只称“可观察 train 前缀累计”，不称真实 lifetime。

### U3 建议公式

使用 H50 每条历史事件自己的字段，不读取 target place/platform：

- ratio 均值为 `Σ(ts_i/duration_i)/N_valid_ratio`，**不是 Σts/Σduration**。>1 不自动裁成 1。timespent=255 是旧卡所记疑似截断，是否沿 F3 原值、是否 clip 待裁决；如 clip，只能 train fit 后固定，不因 validation 效果调整。
- like 率为 H50 中 like=True 数 / 有效曝光数，不称 CTR。missing 不等于 False；建议完整反馈，若允许部分缺失须固定有效分母和 missing 状态。
- 主要场景与平台分别求边际众数，不做联合类别；按曝光事件频数计。建议并列时取 train 词表最小 raw id，确定性复现；不按 target 场景或 like 率破平局。tie/分母/OOV 比例只作诊断，不新增模型输入。

“口味画像”只是行为摘要工作名，不推断敏感属性或真实内容兴趣。无法证明字段存在、合法或当前可用则 UNKNOWN，不用其他属性代填。

### 模型接法建议

在 F4-T010 池化后加对应的 64D 桶/类别 embedding 之和。U2、U3 分开与同 seed anchor 比；不加 MLP、Q2、注意力或交叉特征。item 塔、N1、L50、温度0.10、初始化、batch、LR、epoch/early-stop 预算保持。新表在完整 anchor 初始化后创建，旧参数逐位相同。表数、桶数和参数量待拟合/裁决，当前 UNKNOWN。

加性接法匹配现有结构，但增加参数，不能把收益全归到新信息。U2/U3 组合属于 F8，不以“诊断”名义偷偷加跑。

## 4. 严格前缀与 full-train 必须区分

| 对象 | train 样本 | validation | 禁用或另裁决 |
|---|---|---|---|
| U2 数值 | 同用户 position < target 的快照 | 全部 train 00–24 快照 | 全 train 用户总量回填每个训练 target |
| U3 数值/众数 | 裁决窗口内的严格前缀 | 仅 train 00–24 对应历史 | target、未来、week25 行 |
| 桶边界/类别词表 | 只用 train examples 的合法前缀 fit，一次固定 | 仅 transform | validation/test fit 或 validation 扩词 |
| target/query week | 仅身份/截止校验 | 仅 week25 身份校验 | 输入模型、距 target gap 或绝对周 |

**不继承 C/D 偏离**：decision_log 16:0x 已登记 C/D 物品统计采用 full-train、训练样本可含自身 target 及之后行。用户画像更易编码“训练 target 是 like”，F7 不自动获得该例外。建议严格前缀；任何 full-train 用户回填请求停在设计层，由 Kiro 记录偏离、限制并按权限交 Eddy 决定，不默默实施。

每样本数值严格前缀，与全局 transform 在全部合法 train 前缀上 fit，是不同问题。manifest 分开记录，不能只写“train-only”。anchor 原有 support/logQ 等全 train 口径仍固定，不能据此声称整个系统没有任何训练侧全期信息。

## 5. 接口与预检计划

1. `history_v2.build_observed` 在当前行写入前记录 observed_counts，是累计曝光 snapshot 的先例。它返回 full_lengths，**write_prepared 不持久化逐例 full_lengths**，只写 length-stats 汇总；不能反推逐例值。
2. 同函数 `slices.user_like_counts` 是 **full-train 总量**，只用于切片，不能用作训练 U2 的前缀 like 数。需独立的 per-target snapshot。
3. history_side 固定位置提供 feedback bits/timespent/duration，history_ctx 提供 place/platform。两者仅含已选 history positions，loader 截后缀；L100 也不是无限累计。U3=H50 可复用字段语义，U2=L 需新聚合。
4. 建议独立 query 级 sidecar，按 example_id、validation 原顺序及用户身份对齐；train/export/verify 共用 loader。manifest 绑定 source commit、train 分区 hashes、history/query/catalog hashes、duration metadata hash、prefix/window policy、fit 样本集合 hash、桶/词表 hash、config/seed；不公开用户级原始统计。
5. 后续获授权、冻结后再做真实 train 只读 preflight，仅投影需要列，不输出原始行。核 schema/dtype、missing、值域、duplicate、duration coverage、顺序、target/cutoff、hash；失败即停，不猜默认值。

| 字段/产物 | 本轮可证明 | 当前真实输入 |
|---|---|---|
| user_id/item_id/like、week/ordinal | history-v2 代码要求类型/身份一致 | 未复查，UNKNOWN |
| timespent/duration | side 代码要求合法范围及 catalog duration 全覆盖 | 未复查，UNKNOWN；旧审计不能充当本轮 preflight |
| place/platform | ctx 要求 uint8，FEAT-02 有 train 词表常量 | 当前覆盖与语义稳定性 UNKNOWN |
| 不截断 per-target 聚合 sidecar | 已读写盘接口没有提供所需逐例产物 | 未证明可用，后续须新增并验收 |

分桶 fit 待裁决：count 可用预注册整数网格或 log1p；ratio/like 率可用预注册网格或 train 分位点。只能选定一套后 fit，不能 validation 择优。须固定逐例/逐用户拟合权重、合并阈值、clip、边界包含规则。当前这些数值均 UNKNOWN；拟合只读 train examples 合法前缀。validation 使用同边界，超范围落预设尾桶，不动态扩桶。

## 6. 无画像、missing 与 OOV fallback（建议待裁决）

- 不建可学习 user_id 表。主 query 集及无历史排除规则沿 anchor，不为 F7 改分母；cold-start 若另测只独立报告。
- 完全无画像：新增 F7 向量贡献为 0，回到同 query 的 F4-T010。有效零 like 与无画像分开。本应有 artifact 却缺行/hash 错时 fail-closed，不能 fallback 掩盖损坏。
- 缺字段、duration≤0、有效分母=0 不直接做除法或补有效零。是否容许部分画像待裁决，建议字段级零贡献并保留 missing 诊断；非法输入不能伪造成合法画像。
- place/platform OOV 与 PAD 均零贡献、不可训练；其余可用字段照常贡献。validation 不扩词表，不新增可学习 OOV 画像。
- item OOV/support/catalog 沿 F4-T010；F7 不改 item 向量、不静默剔除 target，也不让不可达 target 凭画像变可达。
