# VK 项目总章程（草稿，2026-11-04）

状态：草稿，等 Eddy 拍板。标「待定」的地方由 Eddy 决定。章程定稿后优先级高于旧计划（tasks.md、旧冻结卡），但旧的实验结果和决策记录保留不删。

## 1. 为什么做

- **主要目的**：找实习时有一个讲得清楚、有一点自己东西的生成式推荐项目。
- **顺带**：把生成式推荐从原理到工程学一遍。
- **性质**：个人独立项目，不商用，不发论文。凡是能查到的论文和代码都可以拿来学习、借鉴、组合。

## 2. 研究问题（暂定一个，最多一个）

> **短视频数据没有文本时，生成式召回该怎么给物品编号（SID），又该学什么目标？**

- **A. SID 从哪来**：比较三种来源——官方 64 维内容向量、行为共现（协同）向量、两者融合；再加上别人已有的可变长度 SID 作参照。
- **B. 学什么目标**：除了 like，再试 D2Q 式的「时长去偏观看标签」，即按视频时长分组、用组内分位数当标签。看它对传统召回和生成式召回分别有什么影响。
- **对照组**：传统召回（双塔 / 我们已有的 M1-mean）、热门、别人在 VK 上的生成式结果。
- **我们自己的东西**：协同信号和内容信号融合成 SID，再配时长去偏标签。这个组合在 VK 上没人做过（待调研确认）。结果是负的也照实写，负结果本身也有分析价值。

## 4. 借鉴原则

1. 每个模块先找现成实现：搜 GitHub、论文代码、教材，记一行「用了谁、为什么」。
2. 先原样跑通别人的结果（复现），再接上我们的数据，最后才改。
3. 自己写的部分只限于：数据接口、评估对齐、我们的研究改动。
4. 别人的代码以依赖或 submodule 的形式引用，并注明来源。公开仓库里不整段拷贝没有开源协议的代码（不是法律风险问题，是基本的礼貌）。

候选底座见 `docs/research_survey_2026-11.md`。第一候选是在 VK 上做过实验的 varlen_semantic_ids（MIT）。

## 5. 完成标准（全部达到 = 项目完成）

1. **复现**：在我们的规模上跑通至少一个别人的生成式基线，数字和它的论文同量级，或者能说清楚为什么不同。
2. **主实验**：§2 的 A 组比较完成，每个配置 3 个 seed，结果写进一张表。
3. **加分实验**：§2 的 B 组至少完成一组（like vs 去偏观看标签）。
4. **最终数**：最后只读一次 test，按事先定好的规则报数。
5. **交付物**：
   - GitHub README：一张结果表 + 一张架构图；
   - 一篇 2–3 页技术报告；
   - 一份 5 分钟面试讲稿：讲问题、做法、结果、踩过的坑。
6. 到这里就停。新想法记进「以后再做」清单，不往本项目里加。
